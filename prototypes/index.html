PikoCI — UX prototypes

Twelve interactive layout paradigms over the same fake dataset (3 teams, 5 pipelines, a live "running" build, a deploy waiting for approval, a failed docs build, a failing resource check, a stuck pending build). Every prototype covers the full app surface: dashboard, pipeline, jobs, builds + logs, resources & pinning, approval gates, HCL config, teams, workers, audit, settings.

Try in each one: find why the docs build is red → how many clicks to the error line? · approve the pikoci deploy (it's waiting) · watch test-integration (it's running and streams live) · find the stuck terraform build and why it's stuck. Scoring criteria live in REQUIREMENTS.md §4; the survey behind the paradigms in RESEARCH.md.

01 Graph-first

Concourse
The DAG is the pipeline page; nodes are the navigation. Dashboard is a wall of mini-graph cards.
structure ★matches PikoCI model Weak at: flat lists, many-pipeline nav.

02 Runs-first

GitHub Actions
Commit-centric run list; run page = job sidebar + step-collapsed dark log. Matrix jobs grouped.
familiarity ★time-to-log ★ Weak at: cross-pipeline overview, DAG comprehension.

03 Stage columns

GitLab CI
DAG layers rendered as stage columns of job pills; pipeline list rows carry mini stage-dots; job page = log + metadata sidebar.
scanability ★ Weak at: deep/wide DAGs, resource-centric thinking.

04 Waterfall

Buildkite
A run is a timing chart: waterfall + table views over the same build, dockable log panel (bottom/right).
perf insight ★multi-view Weak at: first-time simplicity.

05 Wallboard

CCTray · Concourse HD
Big status tiles for the office TV (📺 toggle), attention ticker on top, tiles drill into job tiles then logs.
time-to-red ★glanceable Weak at: dense information work.

06 Miller columns

Finder · TeamCity tree
Team → pipeline → job → build as side-by-side columns; every level visible at once, detail pane on the right.
orientation ★scale ★ Weak at: structure (no DAG picture).

07 Terminal

k9s · lazygit
Keyboard-first dense monospace UI: j/k navigate, enter drills, / filters, t trigger, a approve, : switches views, ? help.
speed ★daily-driver Weak at: discoverability, mouse users.

08 Trace

Dagger Cloud
Every build is a trace of spans with a timeline; first failure surfaced in a dedicated error box; log pane per span.
why-failed ★why-slow ★ Weak at: pipeline-level structure.

09 Activity feed

Vercel · Netlify
One reverse-chron stream of every build across teams; expand in place, approve/retry in place; filter chips; phone-friendly.
what-happened ★mobile ★ Weak at: structure, org-scale noise.

10 Dense table

TeamCity · Jenkins classic
Max information per pixel: weather icons, duration sparklines, change correlation ("Changes" view), favorites, inline actions.
density ★ops ★ Weak at: beauty, newcomers.

11 Attention inbox

novel (triage queue)
Home is a ranked inbox of everything needing a human — approvals, failures with inline error, stuck builds, failing checks, forgotten pauses — with one-click actions. Green work stays collapsed.
action proximity ★inbox-zero Weak at: browsing healthy state.

13 Synthesis recommended starting point

layers 11 + 01 + 10 + 02 + 04 + 08 + 07
One answer to "which one handles all the concerns": attention inbox strip on top of a card wall (home) · pipeline page where graph / table / runs are toggles over the same data · error-first build page with collapsible step logs and build history strip · waterfall at run level · ⌘K palette + f next-failure + / filter as accelerators, never the only path.
Each paradigm survives as a layer where it wins, instead of a destination that must carry everything.

14 Change-centric PR / automated-test mode

fixes 13's blind spot: concurrent PRs
The change (PR/commit) becomes a first-class axis: PR rows with per-job dots, every graph and waterfall scoped to one commit (with a "mixed latest" mode kept only to demonstrate why unscoped coloring lies), ownership-scoped inbox (your failures vs. their failures vs. trunk), superseded commits auto-cancelled and demoted, fork PRs gated behind "run CI with/without secrets", queue-position surfacing.
Compare with 13 on the same question: "why is my PR red?" — then note what 13's pipeline-centric home cannot answer.

12 Canvas map

spatial / infinite canvas
Every pipeline is an island on one pan/zoom map — the whole org is literally a single picture; click nodes for a HUD with builds and actions.
mental map ★ Weak at: text tasks, accessibility, very large orgs.
